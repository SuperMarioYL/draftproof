# DraftProof — provenance Agent Skill（草稿）

> **状态：m3 里程碑草稿（v0.1 预览）。**
> 本文件描述的 CLI 能力（init / watch / log / export / verify）已在 v0.1 完整实现并通过测试；
> 但本 Skill 封装**尚未**在国产模型 agent 宿主（Qwen / GLM / DeepSeek 生态）上安装验证，
> 交互协议以 CLI 为准。宿主验证与定稿在 m3 里程碑（v0.1.x）完成。

## 这是什么

把「这份稿子是被一个真实的人在一个时间跨度里写出来的」变成机器可验的证据：

- 写作目录的每次保存（任何编辑器）都追加一条 **ed25519 签名**的哈希链快照；
- 草稿、密钥、快照全部留在本机，**零网络**；
- 被知网/维普等 AIGC 检测误判时，导出 `receipt-*.dpb` + 可打印 HTML 时间线；
- 学位办/编辑部用同一二进制离线运行 `draftproof verify` 复核：PASS = 未篡改，改一个字符即 FAIL 并定位断点。

它是 humanizer 类「消除 AI 痕迹」skill 的**反面**：不改写、不规避、不洗白——AI 协作的内容如实标记为 agent 会话产物，把更可信的过程证据递给裁决者。

## 何时触发

- 用户提到：论文被判定 AI 代写 / AIGC 检测误判 / 知网维普查重申诉 / 想自证写作过程；
- 用户开始一个论文、长文、报告写作项目，希望在写作期间就留存过程证据。

## 使用流程（通过 CLI）

```bash
# 1) 初始化（每个作者一次）：生成密钥 + 密钥卡
draftproof init
#    把密钥卡上的公钥指纹当天发给导师/同学留档（关键！）

# 2) 常驻监听写作目录（用户写作期间保持运行）
draftproof watch <写作目录>

# 3) 随时查看写作时间线
draftproof log <写作目录>

# 4) 被误判当天：导出回执
draftproof export <写作目录> --out <目录>

# 5) 裁决侧（学位办/编辑部）离线复核
draftproof verify <receipt-*.dpb>
```

## Agent 会话的诚实标记（本 Skill 的核心约定）

当宿主 agent 参与协作写作时：

1. **不冒充人类**：agent 生成或改写的段落，在交付说明中如实注明「本段由 AI 协助生成/修改」；
2. **写入被监听目录**：AI 协作的产物同样保存到 watch 监听的目录——保存事件自然进入哈希链，时间戳与增量曲线会如实反映「有一段快速大增量」；
3. **不教规避**：本 skill 不提供任何「让文本看起来不像 AI 写的」的改写。那不是取证，是破坏取证。

回执证明的是**过程存在且未篡改**，不是「没用 AI」。诚实标记让回执在申诉中更有分量，而不是相反。

## 信任边界（必须向用户说明）

- 本地时间戳防不了「换钥匙整链重造」→ 密钥卡指纹要在**写作前**预登记（发导师留档）；
- PASS ≠ 没用 AI；FAIL = 包内容在导出后被改动过；
- docx 按字节哈希、不解析内部；v0.1 不提供逐版可读 diff；
- 未发表草稿不上云：无云端备份、无远程时间戳、无区块链锚定（RFC 3161 仅在「只锚哈希」前提下评估中）。

## 已知限制

- v0.1 仅单机单作者；多设备/团队签名在路线图外；
- `watch` 只追踪 `.docx/.md/.tex`（不区分大小写），忽略 `~$` 锁文件与 `.tmp`；
- 演示脚本 `examples/demo-tamper-reject.py` 可在隔离 HOME 下完整复现「篡改即翻红」。
